第一阶段：核心底座优先

建议不要一口气重做“完美 Agent 系统”。第一阶段目标是把当前原型修成可继续扩展的稳定内核。

推荐的核心架构边界
CLI/TUI/API 入口
Agent Runtime
loop / events / budget
Policy Kernel
permissions / approvals
LLM Layer
OpenAI-compatible first
Tool Runtime
schemas / execution / results
Session Store
messages / tool events
Test Harness
mock LLM / mock tools
A

最小可用核心

修复 build/test、Agent Loop、OpenAI-compatible provider、权限检查、基础 session。最快形成可靠底座。

B

核心 + 基础 TUI

在 A 的基础上重做一个简洁但专业的 TUI 工作台。更有产品感，但范围更大。

C

核心 + 服务 API

在 A 的基础上把 agent runtime 作为 HTTP service 暴露。适合后续接 Web、平台和 worker。

我的建议

选择 A：最小可用核心 作为第一阶段。当前失败的根因在底层不可靠，先把核心闭环跑通，再做 TUI/API。
